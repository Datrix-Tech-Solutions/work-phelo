# DEV deployment: historical restoration

The DEV workflow, host deployment script and Compose configuration are restored
**byte-for-byte** from commit
`64b410cd2b0a52c727bd15b490b1a9e7fc2da061`:

- `.github/workflows/deploy-dev.yml`
- `.github/scripts/deploy-dev.sh`
- `infrastructure/docker-compose.dev.yml`

This restores known historical behavior, not a claim of improved safety. No
application implementation, Prisma migration, Gateway routing/authentication,
Swagger specification or production deployment configuration is reverted.
The subsequent CI step that builds Gateway's config dependency is retained.

## Restored behavior

- Pushes to `dev` run existing quality gates, service change detection, selected
  image builds and SSH deployment.
- Original `dorny/paths-filter@v4` configuration has no explicit baseline/ref.
- Original concurrency uses `cancel-in-progress: true`.
- Changed services select the release SHA image; unchanged services resolve from
  the host's existing Compose env, with historical fallback behavior.
- Compose/helper assets upload to the original shared deployment directory.
- No exact-SHA approval, successful-run artifact/inventory planner, per-attempt
  staging directory or added host lock remains.
- Original runtime preflights, Compose execution, bounded health/reachability
  checks, local successful-image recording and disk maintenance remain intact.
- Compose contains ten application services plus RabbitMQ and Redis, not AI.

## AI availability

The historical rollout does not build/deploy AI, generate its env file, supply
`AI_SERVICE_URL` to Gateway or execute AI migrations. AI eligibility can continue
returning HTTP 503, "Service 'ai' is not configured for this environment".
Dedicated Gateway Swagger remains at `/api/v1/ai/docs` and
`/api/v1/ai/docs-json`; documentation does not imply upstream availability.

All AI implementation, trusted authentication, request integrity, encrypted
persistence, retention, quota and demo safeguards remain in source. No AI execution
is enabled by this restoration. Minimal AI DEV wiring requires a separate reviewed
change. Isolated Gateway/AI protocol tests are retained using an explicit synthetic
eligibility-only fixture; they no longer claim it is generated by DEV deployment.
If an AI container was independently deployed, historical Compose's
`--remove-orphans` may remove it on the next authorized rollout.

## Retained operational risks

Normal deployment automatically attempts Prisma migrations for Auth, HR,
Notification, Subscription, Marketing, Reinsurance, Accounting and Inventory.
Auth, HR, Notification, Marketing, Reinsurance, Accounting and Inventory URLs retain
their original service schemas. Subscription retains its raw base URL and ignored
migration failure (`|| true`); it currently has no runtime migration catalog.
AI migrations remain excluded. No existing SQL or migration history is rewritten.

After application rollout and health checks, Auth seed runs with development
behavior and administrator credentials; failure stops deployment. HR seed follows,
with failure treated as nonfatal. Auth seed can update administrator password/status,
resource/permission templates and demo tenant state; HR seed upserts demo employees,
departments and Auth linkage. Startup Auth permission backfill also remains unchanged.
These operations can modify existing data and are not harmless health checks.

Cancellation may leave partial remote work; there is no new cross-run host lock or
isolated staging. Image reuse relies on host state, not a verified successful-run
ledger. SHA tags are not digest-level immutable, and historical fallback may use
mutable tags. The repository default branch is `main`, so the restored implicit
change-detection baseline can select more services than intended. These limitations
are retained deliberately for exact historical equivalence.

Migration/seed effects are not automatically undone if later rollout or health
checks fail. This change adds no rollback/reset/resolve automation. Actual pending
DEV histories and current data have not been inspected here. A future merge to
`dev` will trigger this automatic, database-mutating workflow; reviewers must
explicitly accept that historical behavior before merging.

## Verification

The deployment regression spec pins all three historical file checksums, original
cancellation/image-selection behavior and eight migration/two seed commands.
Shell, workflow and Compose checks must run without invoking deployment or database
commands. Normal-auth acceptance after a separately authorized deployment includes
existing ERP health and login; AI 503 is expected until separate upstream wiring.
